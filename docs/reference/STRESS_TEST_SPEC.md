## 🚀 4. 클라이언트(PC) 실행 방법

### 방법 1. `run.bat` 대화형 메뉴 (추천)
`run.bat` 파일을 더블클릭하면 콘솔 메뉴가 실행됩니다:
```text
==========================================================
   📱 스마트폰 웹 서버 스트레스 테스트 자동화 도구
==========================================================

 [1] 전체 벤치마크 실행 (정규 시나리오: 각 10초, 쿨다운 포함)
 [2] 빠른 벤치마크 실행 (--quick: 각 5초 단축 테스트)
 [3] 베이스라인 단독 테스트 (Stage 1: c=5, d=10s)
 [4] CPU 집약 메트릭 API 단독 테스트 (Stage 5: c=15, d=10s)
```

```bash

node benchmark_runner.js --quick
```

### 6.3 아키텍처 및 병목 심층 분석
1. **처리량 상한선 수렴 원인 (약 42~44 RPS)**:
   - **40KB 페이로드 전송 대역폭**: 메인 페이지(`/`)가 약 40,000 바이트(39.9 KB)의 인라인 SPA HTML/CSS/JS입니다. 42.5 RPS는 초당 약 **1.7 MB/s (13.6 Mbps)**의 지속 전송량을 의미합니다.
   - **Tailscale WireGuard userspace 암호화**: 안드로이드 유저스페이스에서 동작하는 Tailscale TUN 인터페이스의 패킷 암/복호화 오버헤드가 CPU를 지속 점유합니다.
   - **동적 UTF-8 인코딩**: `serve_blog.py` 핸들러가 매 요청마다 `HTML_TEMPLATE.encode("utf-8")` 40KB 메모리 할당 및 인코딩을 수행함.
2. **동시 연결 50개(Stage 4)에서 10건 타임아웃 발생의 근본 원인**:
   - Python 표준 라이브러리 `socketserver.TCPServer`의 기본 TCP Listen Backlog(`request_queue_size`)가 **5**로 하드코딩되어 있습니다.
   - 순간적으로 50개의 동시 연결이 요청될 때 커널/소켓 대기열 용량(5)을 초과하여 10건의 SYN 패킷이 드랍/타임아웃되었습니다.
3. **추천 성능 개선 포인트 (향후 필요 시 적용)**:
   - `BlogServer.request_queue_size = 128`: Listen Backlog를 확장하여 c=50 이상에서의 커넥션 드랍 방지.
   - `HTML_BYTES = HTML_TEMPLATE.encode("utf-8")`: 모듈 로드 시 1회 사전 인코딩하여 요청당 40KB 인코딩 연산 제거.
   - `gzip` Content-Encoding 적용: 40KB 페이로드를 ~8KB로 80% 압축하여 Tailscale 전송 대역폭 및 암호화 부담을 5배 절감.
